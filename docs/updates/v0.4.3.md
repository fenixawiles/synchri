# Synchri v0.4.3 — Connection clarity and durable themes

This patch release closes the gap between a passing local readiness check and
a fully verified managed-agent connection, and makes appearance preferences
survive a desktop relaunch.

**Status: implemented and release-ready.**

## Baseline

- **Previous version: v0.4.2**, tagged at commit
  `842ce9f59636d39462feb4f916ac7720981b8c5f`.
- This patch ships as **v0.4.3** from branch
  `codex/fix-runtime-connection-ux`.

## Scope

- [x] Home shows an explicit managed-agent lifecycle: **not connected →
  testing → connected or failed**. Closing the connection dialog does not
  hide an in-flight test or its terminal result.
- [x] The connection dialog separates passive setup readiness from protected
  canary results and always states the next required action.
- [x] A connected runtime is terminal in the setup UI instead of inviting
  repeated tests. A changed executable, version, adapter, or authentication
  state is presented as a re-verification requirement.
- [x] Runtimes without an enforced canary cannot start an impossible test and
  explain that limitation directly. Green readiness checks are never labeled
  as a connection.
- [x] Agent connections remain visible on the first-run home screen before a
  workflow exists.
- [x] Theme selection is stored in Synchri's database rather than browser
  local storage. The server injects the validated preference before first
  paint, so it survives the new loopback port assigned on every app launch.

- Regression coverage includes the explicit background-test state machine,
