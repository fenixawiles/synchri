# Synchri v0.5.0 — Minimalist shell, progressive start, neutral color

This update redesigns the interface around restraint: a business-calm
development environment rather than a terminal cosplay. One global,
collapsible sidebar carries navigation, workflows, recent sessions, and —
inside a session — that session's rail. Pages lead with the next immediate
task instead of exposing everything at once. Color becomes neutral ink with
one muted steel accent; green/amber/red survive only where they carry meaning.

**Status: implemented and verified.**

## Scope

- [x] **Neutral ink color system.** All eleven token blocks are retuned (bare
  root, the byte-identical system-light block, and nine named themes).
  Primary buttons use inverted ink through `--btn`/`--btn-ink`; steel marks
  focus, links, selection, and live state; success, warning, failure, and
  diffs keep explicit semantic colors. The former `terminal` theme key is
  preserved for compatibility and presented to people as **Graphite**.
- [x] **One global, context-aware sidebar.** It replaces the top header and
  holds the brand, New session, Overview, workflows, recent sessions, and
  utilities while browsing. Inside a session, that same sidebar becomes the
  session rail for status, timebox, acceptance progress, tabs, team presence,
  and controls. There is no second telemetry rail. Collapsing it gives the
  conversation the full window and removes hidden controls from the
  accessibility tree; narrow screens use an overlay with backdrop, Escape,
  and close-on-navigation behavior.
- [x] **Home is a start surface.** Actionable and active sessions receive a
  compact attention line; saved workflows are flat launch rows; connection
  status is concise. Session history lives in the sidebar.
- [x] **Progressive new-session flow.** Five questions appear one at a time:
  repository → workspace → brief or *Help me make a plan* → team → Ready.
  Answered steps collapse to summaries with Edit. The recommended team is
  visible before continuing, runtime readiness is shown, repository changes
  reset repository-scoped answers, and switching to planning visibly
  supersedes the build workspace without discarding it.
- [x] **No saved workflow required.** Build sessions can start with the
  recommended Claude-builder/Codex-reviewer pair. Planning sessions use the
  first-class draft API with a UUID-scoped draft per browser flow, so
  interleaved windows cannot overwrite or start one another's ideas.
- [x] **Planning-to-coordination handoff.** A rough idea starts a planning
  room with a planner and adversarial plan reviewer. The approved plan is
  promoted to a coordination session only after the user selects
  **Approve & Start Coordination**; the transition is intentionally not
  automatic.
- [x] **Editorial minimalism.** Palatino Linotype (with Book Antiqua,
  URW Palladio, P052, and Georgia fallbacks) sets a 14px/1.6 book measure.
  Primary content uses type, whitespace, and printed rules instead of cards,
  panel volumes, tinted rows, chips, halos, or pulsing indicators. Monospace
  is reserved for technical values such as paths, branches, commands, ids,
  diffs, and timers. Popovers, dialogs, mobile overlays, and toasts retain the
  elevation needed to distinguish temporary chrome from the page.
- [x] **Accessible selection and motion.** Radio-marked repository,
  workspace, and intent choices expose radiogroup/radio state to assistive
  technology. Sidebar controls expose expanded state and preserve focus.
  Reduced-motion preferences disable the remaining entrance transitions.
- [x] **Compatibility preserved.** The retired wizard is untouched, as are
  externally asserted behavior strings, API routes, native theme persistence,
  and the required theme-token structure.
