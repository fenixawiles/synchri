# Synchri v0.6.0 — Visual identity: the workspace discovers what it is

This update gives Synchri one interface identity instead of three. The chat
workspace becomes the primary product surface — the screen you land on and
the screen you return to — while orchestration (setup, preflight, plan,
gates, artifacts) becomes machinery that surfaces around the conversation
when relevant and recedes when it is not. On top of that sits a real
material system: four elevation levels, soft shadows, one translucent veil,
and restrained motion, all built on the token ladder the themes already
defined. The editorial voice — Palatino, hairlines, small-caps status words,
no cards in prose — stands.

**Status: implemented and verified.**

## Baseline

- **Previous version: v0.5.1**, merged to `main` at `1e4e9dc`.
- This update ships from branch `claude/synchri-visual-identity-up4idc`.

## The critique this update answers

The app inherited three metaphors at once — a chat interface, a pipeline
wizard, and a dashboard — and the seams showed:

- **Boot landed on a dashboard.** `home()` led with workflows and
  connections; the conversation was three full-screen swaps away
  (home → quick flow → preflight → session). Structurally, Synchri was a
  wizard that eventually opened a chat.
- **Everything sat on one plane.** The v0.5.0 minimalist pass removed cards
  and glows but left nothing in their place: `--panel`, `--panel2` and
  `--raise` existed in every theme and were barely used; one `--shadow`
  token appeared four times; two keyframes in the whole file. There was no
  foreground/background distinction — no material difference between the
  page, the working surface, an inspectable panel, and a transient one.
- **Orchestration replaced the conversation instead of surrounding it.**
  The inspector covered the whole main column (`inset:0`); opening any tab
  meant leaving the chat.

What already worked — and is deliberately preserved: the progressive
one-question-at-a-time session flow and its copy, the single context-aware
sidebar that becomes the session rail, SSE with surgical repaints and
draft-preserving conversation updates, the contract/definitions/error
teaching surfaces, and the retired wizard (untouched, as always).

## The system

**Conceptual hierarchy.** Primary surface: the conversation shell — blank
workspace or live session. Primary object: the active session and the work
inside it. Secondary: orchestration state, surfaced contextually (rail,
in-conversation feed, inspector, preflight-as-assembly). Supporting:
repository, specs, plans, artifacts, history. Navigation stays subordinate
in the sidebar.

**Elevation ladder** (the existing per-theme tokens, finally load-bearing):

| Level | Surface | Tokens |
|---|---|---|
| L0 environment | page ground and sidebar | `--bg` |
| L1 working sheet | the raised main column | `--panel`, `--shadow-1`, `--radius-l` |
| L2 inspectable | inspector slide-over, setup sheet | `--panel2`, `--shadow-2` |
| L3 transient | menus, dialogs, toasts | `--raise`, `--shadow` |

Every major element belongs to exactly one level. Content *inside* a
surface keeps the printed-page discipline — typography, whitespace,
hairlines, indentation — never nested boxes. `--veil` (a translucent
panel tint) backs the sticky conversation header so scrolled messages
visibly pass beneath it. Universal geometry and motion tokens
(`--radius-l`, `--dur-1/2/3`, `--ease-out`) live on `html{}`, keeping the
per-theme token audit about color.

**Motion.** Surfaces rise gently from their source (`rise`,
`dialog-in`, the inspector's slide) and settle; state changes ease
(`--dur-2`) rather than flip; the gates bar and team presence transition;
nothing loops, nothing bounces, and `prefers-reduced-motion` still
disables all of it. `document.startViewTransition` is deliberately
deferred: WKWebView only carries it from macOS 15, and the CSS primitives
cover the need.

## Scope

### Foundation: elevation, materials, motion

- [x] **The token ladder is real.** `--shadow-1`, `--shadow-2` and `--veil`
  in all eleven theme blocks (the System-light block stays byte-identical
  to Daylight); universal `html{}` tokens for geometry and motion; the
  token audit extended by `test_the_elevation_and_motion_system_ships`.
- [x] **One raised working sheet.** The main column rides the environment
  on `--panel` with a hairline, `--radius-l` and `--shadow-1`; the sidebar
  stays on `--bg`; flush under 760px so the narrow-screen overlay keeps
  its scroll lock.
- [x] **Material details.** The composer is a raised input that lifts on
  focus; the conversation header is a `--veil` translucency messages
  scroll beneath; menus and dialogs rise instead of appearing; LEDs,
  presence dots and the gates bar ease between states; sidebar and rail
  rows gain a quiet hover tint.

### Orchestration surfaces contextually

- [x] **The inspector slides over the conversation** as an L2 panel with a
  scrim — the chat stays visible and live beneath; scrim click and Escape
  return to it. Rail tools gain quiet group labels (Work · Context ·
  Record) without touching `DETAIL_TABS`; the header's gate count becomes
  a button that opens the Gates inspector.
- [x] **The preflight is the session assembling.** Launch renders inside
  the conversation shell — session name in the header, the checklist where
  the conversation will be, rows rising on durable phase transitions — and
  activation fills the same chrome with the live room.

### The workspace is the product surface

- [x] **The setup flow is a sheet, not a place.** The five-question flow
  keeps its questions, drafts and API calls but rises as an L2 sheet over
  the workspace, entering once and repainting quietly.
- [x] **Boot lands in the workspace.** An active session resumes directly
  into its conversation; otherwise a calm blank workspace: greeting, a
  large brief composer that flows into the setup sheet, workflow
  quick-starts, and the needs-you rows. (Always-blank is a two-line flip
  in `boot()` if the preference changes.)
- [x] **Home retires; nothing it held is lost.** Workflows keep their
  sidebar list and gain `+ New workflow` there; agent connections move to
  a Connections dialog in the sidebar foot; attention rows live on the
  blank workspace.

### Documentation

- [x] This record; `CLAUDE.md` points here; `docs/ui.md` truth pass (the
  editorial shell, the workspace landing, the setup sheet, the inspector
  slide-over, and server-side theme persistence — replacing the stale
  mono-forward/header/localStorage description).
