# Synchri v0.5.1 — Planning correctness, teaching surfaces, mixed teams

This update makes Planning Mode's core loop actually carry the plan, makes
review closure and approval enforce the same rule, honors the promised
"approve what stands", lands approval on the coordination preflight, adds
the teaching surfaces a first-time user needs (contract cover, definitions
on tap, honest errors, gate provenance), and lets one team persistently mix
Synchri-launched agents with agents run in the user's own terminals.

**Status: implemented and verified.**

## Baseline

- **Previous version: v0.5.0**, released from
  `claude/minimalist-ui-redesign-rrbah2` and merged to `main` at
  `b606202`.
- This update ships as **v0.5.1** from branch
  `claude/minimalist-ui-redesign-rrbah2`.

## Scope

### Planning correctness

- [x] **The loop reviews the real plan.** `render_status` carries the latest
  revision's full text, verbatim and untruncated (submissions are already
  capped at `MAX_PLAN_CHARS`), so the reviewer and the cold-relaunched
  planner both read the durable body from their prompts. The conducted E2E
  proves it: the scripted reviewer approves only if a needle unique to the
  stored body reaches its prompt.
- [x] **PLAN-READY implies approvable.** One `validate_criteria()` enforces
  the explicit, collision-free `## Acceptance criteria` rule at review
  closure — an invalid plan returns to the planner with a correction task —
  and re-checks it at approval as defense in depth.
- [x] **Approve what stands.** An exhausted plan with a preserved revision,
  no open blocking items, and valid criteria can be approved from
  `needs_human_resolution`; waivers made there stand as recorded (no forced
  re-review on a spent budget); approval resolves the exhaustion
  escalation; the plan tab explains the three ways forward. The review
  record freezes at approval (`plan_approved_immutable`).
- [x] **Approval lands on the preflight.** The approve handler routes the
  coordination launch payload the endpoint already returned into
  `showLaunch(...)` — startable agents, never an inactive dashboard — as
  **Approve & Continue to Coordination**.
- [x] **Planning is managed-only, honestly.** The launch payload says so,
  the preflight hides "Send prompts instead" with the reason, and an
  unlaunchable roster gets an install/sign-in explanation instead of a
  paste wall that leads nowhere.

### Teaching surfaces

- [x] **Contract cover.** The contract tab (the screen that auto-opens at
  awaiting-acknowledgment) leads with a serve-time human summary — what you
  asked for, who is working, may / ask-first / refused capabilities in
  plain labels, what done means, the timebox, and why agents reply
  UNDERSTOOD — with the agents' exact copy beneath. Existing sessions get
  it too, and it can never drift from the canonical text.
- [x] **Definitions on tap.** Worktree, acceptance gate, session contract,
  and planning workspace are dotted-underline terms at their first
  appearances, opening an accessible dialog; one dictionary, extensible.
  The same definitions ship in `docs/glossary.md`.
- [x] **Honest, persistent errors.** Toasts carrying a resolution stay
  until acted on or dismissed under "Here's how to continue"; bare failures
  auto-dismiss as "That didn't work". New actions: `edit_permissions`
  (previously emitted and silently dropped) opens a session-permissions
  dialog over the existing `control:permissions` endpoint, stating the
  re-acknowledgment consequence up front; planning errors offer the plan
  tab.
- [x] **Gate provenance.** Extraction reports which rule produced the gates
  (`explicit_ids` / `acceptance_list` / `generic_fallback`), sessions
  persist it, promotion stamps `approved_plan`, and the gates endpoints,
  Gates tab, and rail tooltip explain it. Pre-existing sessions stay
  unlabeled rather than guessed.

### Mixed teams

- [x] **A durable managed split.** `managed/start` accepts a participants
  subset; `managed_by_synchri` persists on the roster, and start, resume,
  restart, per-agent restart, and post-restart reconstruction all derive
  the subset from it. Absent flags mean the legacy all-managed shape.
  Planning refuses a strict subset (directives parse only from managed
  stdout).
- [x] **Readiness detail.** `any_available` / `all_available` beside the
  historical `available`.
- [x] **Gated activation.** The managed subset attaches and agrees, then
  the session waits (`waiting_external_setup`, naming who is missing) until
  every externally-run participant acknowledges; Begin collaboration
  activates the room and starts subset supervision in one stroke.
- [x] **Supervision survives external turns.** On `unmanaged_speaker` with
  deliberate externals, the worker holds in a `waiting_external_turn`
  keep-alive and resumes conducting the moment a managed participant gets
  the floor — no human press.
- [x] **One combined preflight.** Managed rows keep real join-phase
  indicators and one Start for the subset; external rows keep the collapsed
  manual fallback; a single external agent no longer forces the whole
  screen through the paste wall.
