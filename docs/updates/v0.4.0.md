# Synchri v0.4.0 — Round 3: session control, live chat semantics, lifecycle & polish

This document marks the baseline this update builds on and tracks its scope.
It exists so any agent or contributor picking up the work can find the full
context in one place.

## Baseline

- **Previous version: v0.3.0**, staged on `main` at commit
  `c8c77277e1612a1535a5b04abec7227c680b15f0` (merge of PR #5, branch
  `claude/synchri-ui-ux-redesign-zkvfzh`).
- At the time this round started (2026-08-16) the `v0.3.0` tag had not yet
  been pushed; the newest published tag was `v0.2.9`. Publishing v0.3.0 is
  independent of this round — tagging `c8c7727` still builds 0.3.0 because
  the version files at that commit read 0.3.0.
- This round ships as **one update, v0.4.0**, developed on the restarted
  branch `claude/synchri-ui-ux-redesign-zkvfzh`.

## Scope — 18 items

Session control:

- [x] 1. "Complete session" actually completes: validation happens before
  agents are cancelled, unmet gates can be explicitly waived from a
  confirmation dialog, and a human marking a gate "pass" counts.
- [x] 2. "Stop session" actually stops: agent process **groups** are
  terminated (not just the CLI wrapper), including during the agreement
  phase.
- [x] 8. Gate detection recognizes plain-text acceptance sections, detected
  gates are shown before launch, and gates can be added from the Gates tab —
  the single hardcoded `SPEC-01` fallback becomes a true last resort.

Agent lifecycle:

- [x] 3. Agents that drop mid-session can be restarted (`Restart <agent>`).
- [x] 13. Agent failures are flagged loudly: per-agent runtime state, chat
  banner, rail status; two consecutive hard failures drop the agent and
  raise an escalation; clean-exit low-signal turns get a warning.
- [x] 18. Manual agent naming removed — names derive from the runtime
  selector (with `-2` style dedup).

Chat experience:

- [x] 5. Chat input becomes a wrapping, auto-growing composer
  (Enter sends, Shift+Enter for a new line).
- [x] 6. Real streaming ingestion for Claude Code (`stream-json`) and Codex
  (`--json`): live status, reasoning snippets, tool/command lines,
  compaction notices — chatbot-style, not one terse sentence.
- [x] 7. Live, collapsible per-file diff cards in the chat as agents edit,
  for every agent; structured outputs with hierarchy, red/green insertion
  text, and truncation for oversized blocks.

Diffs & commits:

- [x] 9. Commit ids link to the commit on GitHub.
- [x] 10. Changes tab shows one collapsible card per changed file (including
  uncommitted work) instead of one long diff.

Setup flow:

- [x] 4. Worktree choice is an explicit, mandatory selection — even "new
  worktree" must be chosen, never assumed.

Sessions:

- [x] 15. Sessions can be renamed and deleted like workflows. Deleting never
  loses git history: the session worktree is only auto-removed when clean
  and fully pushed.
- [x] 12. Terminal sessions produce a downloadable package: transcript,
  usage summary, changelog, gates, commits, diff.

Home & editor:

- [x] 16. Workflows and the "New workflow" action become the prominent part
  of Home; recent sessions become compact.
- [x] 17. Permission-profile selection highlights the chosen card and gives
  tactile feedback.

Themes:

- [x] 11. Six new palettes (ember, copper, solar, harbor, iris, orchid) so
  the set spans the rainbow across dark and light variants.

Updater:

- [x] 14. The updater rests at "Check for updates"; a manual check shows
  "All up to date!" briefly (or the available version with an install
  prompt) and then returns to the resting state.

## User-confirmed decisions

- Session delete removes Synchri records and room files; the worktree and
  local branch are removed only when provably safe (nothing uncommitted,
  nothing unpushed). Remote refs are never touched. User-selected existing
  worktrees are never removed.
- Clean-exit refusals are warn-only; hard failures auto-drop after 2 strikes.
- The completion package is available for any terminal session, and its
  telemetry is labeled "Usage summary" (tokens, cache tokens, cost,
  duration, per-agent totals — no rate math).

## Watch areas during implementation

1. `manager.complete()` / `stop()` terminal-transition race: every terminal
   transition re-checks state inside its own write transaction; `_finish`
   runs at most once per session.
2. Process-group termination across macOS and wrapped CLIs: covered by an
   automated kill matrix (grandchild, timeout path, agreement phase,
   registry fallback, zombie reaping), not just manual smoke.
3. Stream-event volume vs. the 0.75 s full-repaint UI: server tail caps,
   per-invoke row caps, memoized diff HTML, and a profiling pass in the
   visual smoke.

- Watch area 2: the kill matrix runs in `tests/test_runner.py` — grandchild
