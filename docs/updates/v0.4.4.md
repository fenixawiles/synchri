# Synchri v0.4.4 — Current CLI connection compatibility

This patch release restores protected connection tests for current Codex and
Claude Code CLIs while preserving the read-only boundaries introduced in
v0.4.2.

**Status: implemented and release-ready.**

## Baseline

- **Previous version: v0.4.3**, tagged at commit
  `5b4db0129a18349d175913e49f7e53125f1affe7`.
- This patch ships as **v0.4.4** from branch
  `codex/fix-cli-canaries`.

## Scope

- [x] Codex connection tests include `--skip-git-repo-check`, allowing the
  protected canary to run from Synchri's temporary non-repository directory
  while retaining the OS-enforced `--sandbox read-only` boundary.
- [x] Claude Code connection tests send their prompt over standard input so
  the current CLI's variadic `--tools` option cannot consume it as another
  tool name. The planning-only permission mode, safe mode, strict MCP config,
  and empty canary tool set remain in force.
- [x] Claude Code planning prompts use the same standard-input transport,
  retaining the read-only `Read,Glob,Grep` tool set.
- [x] Resume canaries use the corrected Claude Code transport without
  weakening their protected command.

## Verification record

- Full Python suite: **690 passed**.
- Live protected canaries passed against installed Codex `0.148.0` and Claude
  Code `2.1.240` CLIs.
- Codex passed launch, bootstrap, authentication, and structured-output
  checks; its maintained adapter does not define resume.
- Claude Code passed launch, bootstrap, authentication, structured-output,
  and resume checks.
