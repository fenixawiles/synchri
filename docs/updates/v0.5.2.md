# Synchri v0.5.2 — Deliberative provenance and queryable development history

This update extends Synchri from coordinating agents into preserving,
retrieving, and explaining the deliberative process that produced a change.
After a session — hours or months later — a user can ask *why is this
here?* and receive a concise, plain-English answer grounded in the exact
historical evidence, with drill-down from report to excerpts to timeline to
raw history.

**Status: implemented and verified.**

## Baseline

- **Previous version: v0.5.1**, shipped from
  `claude/minimalist-ui-redesign-rrbah2` (planning correctness, teaching
  surfaces, mixed teams).
- This update ships as **v0.5.2** from the same branch. Version bumps
  remain the release flow's job.

## Principles held throughout

- **The transcript and existing durable records are the canonical evidence
  layer.** Every derived structure indexes and organizes that record;
  nothing replaces it or becomes a second source of truth.
- **Provenance strata are preserved internally**: canonical transcript
  evidence, structured session records, deterministic test evidence,
  repository observations, bounded telemetry, and historian synthesis are
  distinguishable on every result object, whether or not a surface shows
  the label.
- **Epistemic constraint**: explanations are grounded exclusively in
  retrieved evidence. Causal language appears only where a cited excerpt
  states the relationship; sequence and cross-excerpt reconstruction are
  labeled synthesis; what the record cannot establish is reported as
  unresolved — never inferred from temporal proximity or the final code.

## Scope

### Provenance completeness and the deliberation index

- [x] `synchri/session/deliberation.py`: a **deliberative timeline derived
  at read time** — proposal, revision, objection, counterproposal,
  question, evidence, test result, failure, resolution, residual concern,
  acceptance, rejection, phase block, phase completion — assembled
  mechanically from plan revisions and objections, milestone events, gate
  transitions, contract conflicts, blocked turns and approval requests,
  side tasks, and escalations. Every entry carries refs that open the
  exact underlying row, plus its provenance layer.
- [x] Two persistence gap-fills: `session.tests_run` (mid-session test
  runs become durable deterministic evidence) and `session.repo_observed`
  (HEAD plus dirty count after each completed managed turn — correlation
  data, deliberately never narrated into the timeline).
- [x] `GET history/timeline` with kind filtering.

### Hybrid retrieval

- [x] A lazily built search index (schema v8) over messages, plan revision
  bodies, objections and dispositions, gate evidence, side tasks, contract
  conflicts, the idea, the memory ledger, and — best-effort, as bounded
  telemetry — stream titles and file paths. Append-only sources advance by
  watermarks; small mutable sources refresh wholesale per query.
- [x] FTS5+bm25 probed at bootstrap, LIKE fallback otherwise; results name
  the engine. Questions are rebuilt into MATCH form from word tokens, so
  punctuation never breaks a query. Ranking fuses lexical order,
  structured-record signals, and recency by reciprocal ranks; message hits
  bring the message they replied to; results cap at the smallest evidence
  set that fits the budget.
- [x] `GET history/search`; `synchri why "<question>" [--session]`
  (unscoped spans every session).

### The historian

- [x] `synchri/runner/historian.py`: a one-shot **read-only** invocation
  of the user's own installed agent (enforced `planning_command`,
  disposable temp cwd, spend tagged `origin_kind='historian'`), on the
  ancillary-scout pattern.
- [x] **Fail-closed grounding**: reports must cite `[En]` evidence markers
  in their evidenced sections; uncited or out-of-range replies are refused
  server-side. `INSUFFICIENT: …` is an accepted, honest answer. The
  causal-language rule is stated in the prompt contract verbatim.
- [x] The mechanical floor is always present: no runtime, a failed
  invocation, or a refused reply all return the identical shape with the
  reason named, plus the evidence and timeline.
- [x] `POST history/ask`; `synchri why --report` as an explicit opt-in to
  one provider invocation.

### The History surface

- [x] A History tab (between Memory and Raw) with progressive disclosure
  over one provenance: report → cited evidence (each `[En]` marker opens
  the exact excerpt with its ref and layer) → kind-filterable deliberation
  timeline → the Raw tab as the forensic floor. Honest empty,
  insufficiency, and fallback states; a defined "recorded history" term;
  editorial design language; no browser storage.

### Documentation

- [x] README: "Ask why, later" under How a session works, stating the
  grounding rules plainly. Glossary: deliberation timeline and historian
  report. This record.
